# Phase 1 实验与交付记录

记录日期：2026-10-15（Asia/Shanghai）。所有数值来自此工作区实际运行；没有训练、云 API、合成视频冒充公开样例或人工审核冒充。

## 结论与适用范围

端到端工作台已经运行：真实本地输入 → 运动候选 → 本地 VLM → 证据帧 → 回放/编辑/审核 → 可播放 MP4 + JSONL + ZIP。**尚未证明可靠发现危险驾驶事件。** 当前候选是视觉变化提案，模型描述是待审核推断，默认无精确风险等级。

最终默认 2.2B 模型在三个小型原始路侧片段中提及的对象类别更完整，代价是更高内存/时间。但它仍会编造时间关系、概括交通密度变化，不能把对象类别核对结果推广成完整描述正确率或事故检测精度。

* 完整依赖版本：[environment-macos.lock.txt](environment-macos.lock.txt)。这不是跨平台 CUDA wheel 锁文件。
* 模型固定版本：2.2B `482adb537c021c86670beed01cd58990d01e72e4`；256M `067788b187b95ebe7b2e040b3e4299e342e5b8fd`。下载器依赖 Hub 的完整性校验，只保存仓库与 revision。

单次测量，未做冷热缓存重复采样或后台进程完全隔离。RSS 是进程驻留内存；Metal 内存另有统计，两者不可简单相加或误认为整个系统峰值。

## 三个原始片段的独立类别核对

从 [TUM 官方公开分卷](https://accident-dataset.github.io/) 中通过 HTTP Range + ZIP CRC 校验按需获取原始 JPEG 和 OpenLABEL；没有下载整个 9GB 分卷。第三个序列的标签位于第二分卷，已补齐，**缺失标签不会当负例**。

选择规则在模型分析前固定：`r09_s02/r09_s03/r09_s04`，`north_50mm` 相机，各取源序列 57–62.5 秒、2fps、12 帧，生成 6 秒 sample-and-hold 视频。共 36 原始图像、18 视频秒；并非原始 25fps 连续录像。模型各查看 6 帧；评估使用这些证据对应的官方标签。原始图像无叠加检测框。

评分单位是“某类别是否在该片段被提及”。预先定义 CAR/TRUCK/BUS/PEDESTRIAN/BICYCLE/MOTORCYCLE 六类，使用简单英文词项提取；对原文逐条保留，避免只输出总分。推理不读标签，未做本地训练。

| 模型（同一 v3 预处理/prompt） | 有标签支持的类别提及 | 无标签支持的提及 | 漏提类别 | Mention precision | Mention recall | 运行时间含冷加载* |
|---|---:|---:|---:|---:|---:|---:|
| SmolVLM2-256M | 3 | 0 | 8 | 3/3 = 100% | 3/11 = 27.3% | 10.37s |
| SmolVLM2-2.2B | 8 | 0 | 3 | 8/8 = 100% | 8/11 = 72.7% | 48.28s |

\* 包含三个新视频导入/索引和推理，不包含最后导出。RSS：256M 为 1.77GiB，2.2B 为 3.82GiB。样本太小，不做显著性/泛化判断；某类别未被模型提及不等于检测失败，描述器并未被要求穷举所有对象。

**100% 仅表示这 3 个小片段的 3 或 8 个类别词没有与已有标签冲突，不代表描述完全正确，更不代表事故精度。** 这些片段来自官方 train 分卷，不是官方测试集；不能排除同一事故/行程相关性或模型预训练污染。

2.2B 漏提包括小型行人和公交对象；256M 多数只说“高速上有汽车”。2.2B 同时存在“不同时间段/一天中的不同时间”“交通增加意味着拥堵减少”等无证据推断，此类别指标捕获不到。

可审计记录：[2.2B 类别核对](object-claims-evaluation.json)、[256M 类别核对](object-claims-256m.json)、[2.2B 运行](raw-subset-run.json)、[256M 运行](raw-subset-256m-run.json)。来源时间/哈希/标签位置在 `data/public/tum-raw/subset-manifest.json`，由 `scripts/fetch_tum_subset.py` 重建。

## 发现与修复的真实问题

1. **默认图像预处理不适合帧预算。** 初版将每张输入放大到 1536/2048px 并切块。256M 常列举不存在的第七、第九帧、行人和碰撞；2.2B 单候选曾耗时 69.45s，内存压力拖慢浏览器导出。修正为模型原生视频边长，关闭 image splitting；保存输入 token 数和张量形状，增加回归测试。
2. **提示词暗示事故。** 初版 prompt 提到 collision，结合小模型错误产生无证据事故叙述。v3 改成只描述可见对象/位置，不先验提示危险类型。保留失败响应，未把它们改写成正确答案。
3. **多模型重复提案计数。** 同一视频的不同模型运行不应算新增事件。工作台默认最新分析，历史版本可显式查看；原始证据和人工修订始终保留。
4. **评估标签分卷。** 初步读取第三段时没有找到标签；检查后发现标签在下一 ZIP。评估脚本对未知参考不评分，补齐后才生成最终数值。
5. **浏览器检查。** 修复手机端缺少视频选择入口；下载测试显式跟踪本次任务，避免误用历史 ZIP 链接。较早测试脚本相对 URL/任务等待失败的结果不计作通过。
6. **导出可追溯性。** 精确裁剪重新编码，支持浏览器 Range；修订边界不丢原模型证据，导出完整源许可说明，文件哈希覆盖 manifest 本身以外的全部包内容。

## 工程验证与未验证项目

2026-10-16 整理后通过 **14 项 pytest**（含一个实际离线模型 processor 的可选回归测试；纯核心环境会跳过该项）。涵盖真实解码、候选预算、静态视频不出运动候选、缓存/去重、审核历史/并发修订、边界校验、失败可重试、导出可解码/可校验、跨站写入限制、Range 回放、重启恢复、事件一对一匹配和历史分析隔离。新增测试确保标注程序错误不会被降级隐藏；依赖仍有一条 Starlette/httpx 弃用提示，不影响结果。

浏览器检查结果：[browser-check.json](browser-check.json)，含实际视频元数据、证据跳转、检索无结果状态、实际 ZIP 下载和手机布局检查。截图仅为可选本地输出，不随仓库保存。自动化没有将真实模型输出冒充人工确认；人工审核状态变更由隔离的测试视频验证。

以下指标 **未测得，不能提供数字**：真实危险事件 precision/recall、事故时间定位 tIoU、每小时人工确认有效新增事件、人工审核成本、8GB Mac 峰值资源、4090 速度/质量。通用事件评估器已实现，但本轮取得的 OpenLABEL 是对象标注，不包含可直接复用的异常起止区间。

DoTA 视频包未取得；Nexar 需要用户账号/联系信息与许可确认。后续应使用经授权的固定事件测试集，而不是给当前模型伪标签补上一个“准确率”。
